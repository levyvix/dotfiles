# Rich Issue Template

Use this structure when the repository does not provide a better native issue template.

## Title

Write a short, specific title that names the problem or feature.

## Body

```md
## Summary
[One short paragraph describing the feature or bug.]

## Problem
[What is broken, missing, confusing, or costly today?]

## Current Behavior
- [...]

## Desired Behavior
- [...]

## Scope
- Included: [...]
- Excluded: [...]

## Evidence
- Affected files: `path/to/file.py`, `path/to/other.py`
- Relevant commands: `...`
- Notes: [...]

## Acceptance Criteria
- [ ] ...
- [ ] ...
- [ ] ...

## Reproduction
1. ...
2. ...
3. ...

## Risks and Edge Cases
- ...

## Open Questions
- ...
```

Omit sections that do not apply. For bugs, keep `Reproduction`. For straightforward features, keep `Scope` and `Acceptance Criteria`.
